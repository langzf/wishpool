# WishPool 视觉方向与设计系统基线

版本：v1.0  
日期：2026-08-12

## 1. 设计目标

WishPool 的视觉目标不是把任务包装成强游戏，也不是做家长管理后台。产品需要同时满足：

- 儿童端：温暖、清楚、低压力、愿意主动打开。
- 家长端：克制、高效、10-30 秒能完成审核。
- 家长 Web：适合批量配置、整理纪念册、查看长历史。
- 运营后台：工作台风格，信息密度高、权限清楚、审计可追踪。

## 2. 竞品机制借鉴

竞品中值得借鉴的是体验结构，不是视觉照搬：

| 类型 | 可借鉴点 | WishPool 取法 |
| --- | --- | --- |
| 儿童任务/家务 App | 儿童能看到清晰任务、进度、奖励结果 | 今日任务保持大目标和少操作，避免复杂任务经济系统 |
| 家庭奖励 App | 家长配置任务、孩子完成、家长确认 | 家长端保留快审卡片，不做复杂积分商城 |
| 儿童习惯养成 App | 连续完成后有徽章、空间变化 | 小屋变化只来自真实成长和家长精选 |
| 家庭纪念册/相册 App | 照片、声音、留言长期沉淀 | 成长纪念册自动生成周卡，家长可轻量精选 |
| 儿童金融/零花钱产品 | 清晰进度和目标感 | 不引入金钱奖励，不把任务变成交易 |

参考来源包括 Joon、Homey、GoHenry、Chore Pad 等儿童任务、家务、奖励和家庭协作产品。WishPool 只吸收任务可见性、目标进度、家长确认和长期记录这些机制，不采用金币商城、公开排行或强金钱奖励作为视觉中心。

## 3. 产品气质

关键词：

- 儿童端：星光、木屋、纸张、贴纸、成长、亲密。
- 家长端：清爽、安静、明确、少打扰。
- Web/后台：秩序、扫描、效率、可靠。

避免：

- 过度霓虹、复杂赛博风。
- 大量紫蓝渐变。
- 一屏堆满卡片。
- 商城化、金币化、装备化。
- 儿童端出现家长管理术语。

## 4. 颜色系统

### 4.1 品牌色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `brand.sky` | `#67B7DC` | 主品牌、心愿进度、儿童端主按钮 |
| `brand.sun` | `#FFD166` | 星光、解锁、积极反馈 |
| `brand.leaf` | `#7BC67E` | 完成、通过、成长 |
| `brand.coral` | `#F28B82` | 温和提醒、退回修改 |
| `brand.ink` | `#253047` | 主要文字 |

### 4.2 Surface

| Token | 色值 | 用途 |
| --- | --- | --- |
| `surface.canvas` | `#F7FAF8` | App 背景 |
| `surface.paper` | `#FFFFFF` | 面板、表单、审核卡 |
| `surface.soft` | `#EEF6F4` | 儿童端柔和区块 |
| `surface.night` | `#24324A` | 心愿解锁、夜晚小屋场景 |
| `border.subtle` | `#DCE7E3` | 轻边框 |

### 4.3 语义色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `success` | `#2EAD6B` | 通过、完成 |
| `warning` | `#F5A524` | 需要注意 |
| `danger` | `#D64545` | 删除、严重错误 |
| `info` | `#3B82C4` | 信息提示 |

规则：

- 功能颜色必须配合文字或图标，不只靠颜色表达。
- 儿童端背景可以温暖，但正文对比度必须达标。
- 家长端和后台不使用大面积装饰渐变。

## 5. 字体与排版

移动端：

- 中文优先使用系统字体：iOS `PingFang SC`，Android `Noto Sans CJK`。
- 英文/数字使用系统 Sans。
- 儿童端标题可使用更圆润的字重和尺寸，但正文保持清晰。

字号建议：

| Token | 移动 | 平板 | Web |
| --- | --- | --- | --- |
| `display` | 28 | 34 | 36 |
| `headline` | 22 | 26 | 28 |
| `title` | 18 | 20 | 22 |
| `body` | 16 | 17 | 16 |
| `label` | 13 | 14 | 14 |
| `caption` | 12 | 12 | 12 |

规则：

- 不用负字距。
- 正文行高 1.5。
- 按钮文字不得小于 14。
- 儿童端关键信息要一眼可读。

## 6. 布局与组件风格

### 6.1 儿童端

一级导航：

- 小屋。
- 今天。
- 心愿。
- 回忆。

布局：

- 平板优先，主内容居中，左右保留呼吸空间。
- 小屋首页可以是沉浸式场景，但操作按钮必须明确。
- 今日任务使用大行距任务列表，状态图标固定尺寸。
- 任务详情一次只展示一个任务，不放复杂配置。

组件：

| 组件 | 风格 |
| --- | --- |
| 任务卡 | 轻边框、8px radius、明确完成状态 |
| 心愿拼图 | 固定 5/7/10 块可扩展网格，亮起动画短 |
| 星光反馈 | 小粒子或光点，控制在 1 秒内 |
| 反馈弹窗 | 家长头像/称呼 + 语音/文字，按钮大 |
| 小屋元素 | 真实行为解锁，照片墙/书架/徽章 |

### 6.2 家长移动端

一级导航：

- 今天。
- 审核。
- 心愿。
- 回忆。
- 设置。

布局：

- 今日首页展示完成概览、待审核、当前心愿。
- 审核卡片首屏只保留缩略图、AI 摘要、通过、退回、反馈。
- 语音反馈入口必须单手可达。

组件：

| 组件 | 风格 |
| --- | --- |
| 审核卡 | 信息密度中等，主要按钮突出 |
| AI 摘要 | 明确标记“AI 建议”，用浅色信息区 |
| 通过按钮 | 绿色语义，带勾图标 |
| 退回按钮 | 次级或温和提醒色，不做危险红 |
| 语音按钮 | 麦克风图标 + 录制进度 |

### 6.3 家长 Web

布局：

- 左侧导航 + 顶部家庭/儿童切换。
- 主区适合表格、日历、时间轴。
- 周计划使用周视图和模板侧栏。
- 纪念册编辑使用左右分栏：内容列表 + 预览。

### 6.4 运营后台

布局：

- 高密度工作台。
- 表格、过滤器、审计详情、状态标签。
- 原始媒体默认不展示。
- 敏感访问必须有授权弹窗和审计提示。

## 7. 组件尺寸

| 组件 | 移动 | 平板/Web |
| --- | --- | --- |
| 触控目标 | ≥44pt | ≥40px |
| 主按钮高度 | 48-56 | 40-48 |
| 图标按钮 | 44x44 | 36x36 |
| 卡片圆角 | 8px | 8px |
| 输入框高度 | 48 | 40 |
| 底部导航高度 | 64 + safe area | 不使用 |

规则：

- 不做嵌套卡片。
- 页面分区用全宽带或自然布局，不把每个区域都浮成卡。
- 固定格式组件必须有稳定尺寸，避免状态变化导致跳动。

## 8. 动效原则

动效只服务反馈和空间关系：

- 心愿碎片亮起：300-600ms。
- 任务完成反馈：200-400ms。
- 家长反馈弹窗：从底部或中心轻入场。
- 小屋元素解锁：800-1200ms，不能阻塞继续操作。
- 页面切换：遵守平台方向。

必须支持 reduced motion。

## 9. 图标与插画

图标：

- Web 使用 Lucide。
- Flutter 可使用 Material Symbols 或统一图标字体。
- 图标线宽保持一致。
- 不使用 emoji 作为功能图标。

插画：

- 小屋、星光、拼图、徽章可以使用矢量或 Rive/Lottie。
- 照片和纪念册必须优先展示真实家庭媒体。
- 插画不能压过任务本身。

```text

typography/
spacing/
radius/
shadow/
motion/

breakpoints/
```

Spacing：

```text
4, 8, 12, 16, 20, 24, 32, 40, 48, 64
```

Radius：

```text
4, 8, 12
```

Cards 默认 8px。儿童小屋中的装饰物可以更圆润，但工具型 UI 控件不超过 8px，除非是圆形图标按钮。
