# WishPool 完整能力验收清单

版本：v1.0  
日期：2026-08-13

## 1. 目标

本文作为 WishPool 工程验收基准，逐项记录完整产品所需能力、当前实现深度、缺失项和完善顺序。清单覆盖服务端、worker、移动端、家长 Web、管理后台、前后端接口、交互、本地部署和质量保障。

验收口径：

- 服务端能力必须包含真实状态机、权限、事务、事件、幂等、审计和测试。
- 客户端能力必须包含真实页面、表单、媒体/录音/上传、错误反馈、加载状态、本地缓存、同步和可访问交互。
- 接口能力必须以 OpenAPI 为事实契约，客户端不得长期绕过契约读取样例数据。
- worker 能力必须能被事件或内部 API 驱动，失败可重试，结果可追踪。
- 自用本地部署也必须具备可维护、可恢复、可观测的完整闭环。

## 5. 完善顺序

| 顺序 | 工作包 | 依赖 | 验收 |
| --- | --- | --- | --- |

| 2 | 移动端认证、家庭选择和儿童配对 | 聚合 API、Auth、Pairing | 家长和儿童设备都能建立会话 |

| 6 | Web 完整管理体验 | 聚合 API、写命令 API | 家长 Web 可处理高密度计划、回忆和设置 |
| 7 | 管理后台真实治理 | Admin API | 隐私、审计、媒体授权和服务健康可用 |
| 8 | 模型、推送和部署治理 | AI provider、Push adapter、infra | 本地部署可长期维护，并可接入真实模型/推送 |
| 9 | 端到端质量保障 | 全部模块 | 自动化覆盖核心家庭闭环 |
