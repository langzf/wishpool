# 心愿与计划页面设计重构方案

## 1. 现状问题诊断

### 家长端计划页

- 信息层级偏平：今日任务、模板库、本周规则、编辑器都使用同一种 `panel` 样式，用户难以先看到“今天要处理什么”和“本周节奏是否合理”。
- 缺少计划感：计划规则只是行列表，没有周视角、核心任务占比、执行节奏等概览，无法形成“本周安排”的整体印象。
- 操作路径分散：模板创建、模板加入、本周规则保存都在不同面板内，视觉上像后台表单，缺少家长可快速理解的工作流。
- 情感表达弱：K12 亲子场景需要轻量激励与成长语境，目前文案与视觉偏工具化。

### 家长端心愿页

- 只展示当前心愿和创建表单，缺少当前心愿、历史心愿、心愿卡库、统计之间的层级。
- 当前心愿以标题、说明、线性进度条呈现，没有“心愿卡”和“碎片集满”的视觉隐喻。
- 历史心愿与兑换留存没有在心愿页出现，家长无法从心愿页回看照片、文字记录和兑现次数。
- 创建路径单一：只能新建，不能从历史心愿复用已有卡片再次许愿。
- 空状态只是说明文字，没有引导家长选择历史卡或创建第一张心愿卡。

## 2. 心愿页信息架构

页面按从“当前推进”到“复用沉淀”的顺序组织：

1. 当前心愿
   - 首屏主模块，展示本周进行中的心愿卡。
   - 包含心愿标题、说明、状态、碎片格进度、已收集/目标碎片、下一步提示。
   - 未创建时展示空卡片，引导创建本周心愿。

2. 统计概览
   - 展示本周进度、历史实现次数、可复用心愿卡数量、兑换照片数量。
   - 统计来自当前心愿、历史心愿和兑换记录聚合，MVP 可由前端根据聚合接口计算。

3. 心愿卡库
   - 从历史心愿按标题聚合出可复用卡片。
   - 每张卡展示最近状态、实现次数、最近备注、默认碎片数。
   - 支持“再次许愿”：用历史卡的标题、备注、碎片数提交到现有创建心愿接口并激活。

4. 历史心愿
   - 展示每次许愿记录，包括完成/未完成/已兑换状态、碎片进度、兑现记录摘要。
   - 点击或展开后查看历史照片与文字留存。MVP 先在同页展开详情，后续可拆为 `/wish/[wishId]`。

## 3. 心愿卡视觉规范

### 卡片布局

- 卡片顶部：状态标签 + 周期或提示。
- 卡片主体：大标题、说明、主题化图形区域。
- 卡片底部：碎片格、进度数字、行动按钮。
- 圆角遵循现有 token，主要卡片使用 8px，避免过大圆角。

### 配色

- 基础色沿用 `packages/design-tokens`：primary 蓝、secondary 绿、accent 橙、surfaceRaised 暖色。
- 当前心愿使用暖色背景承载情感表达，统计和列表保持白底工具感。
- 历史状态颜色：
  - 进行中：蓝色。
  - 已集满/已兑换：绿色。
  - 草稿/未完成：橙色或灰蓝。

### 碎片可视化

- MVP 使用 N x M 响应式碎片格：
  - 默认最多展示 12 格；目标碎片数超过 12 时仍按比例映射到 12 格，数字保留真实值。
  - 已获得碎片显示高亮、轻微阴影和图案层；未获得碎片使用浅色虚线格。
  - 支持 `aria-label` 表达真实进度。
- 后续增强：
  - 心愿卡图片由 AI 或模板服务生成。
  - 碎片可切换为拼图式遮罩，按照片/插画逐步揭开。

### 空状态

- 当前心愿空状态不只显示“还没有”，而是提供两条路径：复用历史心愿卡、创建新心愿卡。
- 历史为空时展示首张心愿卡创建引导。

## 4. 历史心愿详情页设计

MVP 先做同页详情卡，结构如下：

- 顶部：心愿标题、状态、实现次数、碎片进度。
- 照片墙：展示兑换照片缩略卡；没有照片时展示“兑现时可补充 1-3 张照片”的提示。
- 兑现时间线：
  - 兑换日期。
  - 家长记录。
  - 孩子记录。
  - 关联照片。
- 后续独立详情页：
  - 路由 `/wish/[wishId]`。
  - 支持按兑现记录、成长纪念册、关联任务筛选。

## 5. 计划页设计升级方案

- 首屏变成“本周计划驾驶台”：
  - 今日任务处理区：突出待打卡、待审核、已通过。
  - 周计划概览：规则数量、核心任务数量、覆盖天数。
  - 本周节奏条：按周一到周日展示每天任务密度和核心任务。
- 模板库改为“可加入计划的任务卡”，用图标、分类、提交类型、默认说明展示。
- 规则编辑器保留现有能力，但在视觉上放到“编排区”，让家长理解为从模板/自定义任务编排本周。
- 表单输入继续使用现有 server action，避免一次性引入复杂客户端状态。

## 6. 学生端 App 设计方案

- 心愿屏改为孩子视角：
  - 顶部用大标题和鼓励语，避免后台管理口吻。
  - 主体是一张大心愿卡，使用彩色图形、目标名和碎片格。
  - 进度表达为“还差 X 块”“已经点亮 X 块”，弱化百分比。
- 儿童友好控件：
  - 大图标、大点击区域、短句文案。
  - 碎片格尺寸稳定，已点亮碎片用颜色和图标表达。
  - 弹窗展示兑现规则、今日推进方式和最近纪念册。
- 动效策略：
  - MVP 使用 Flutter `AnimatedContainer` 和稳定布局。
  - 后续在碎片新增时增加轻量弹跳和星光反馈。

## 7. 后端能力缺口清单

### 现有能力可复用

- 创建心愿：`POST /wishes`。
- 激活心愿：`POST /wishes/{wishId}/activate`。
- 当前心愿：`GET /children/{childId}/wishes/current`。
- 心愿列表：`GET /children/{childId}/wishes`。
- 兑现心愿与照片留存：`POST /wishes/{wishId}/redeem`，底层已有 `wish_redemption` 与 `wish_redemption_media`。
- 成长纪念册：`MemoryService` 已可按孩子列出 weekly memories。

### MVP 需要补齐

- 聚合历史心愿及兑换记录：
  - 新增或扩展只读 DTO：历史心愿项包含 wish、redemption、realizedCount。
  - 在 parent dashboard 聚合接口返回 `wishHistory`，避免 parent-web 额外串行请求。
- 心愿卡库：
  - MVP 不新增表，通过历史心愿按标题聚合形成“可复用卡片”。
  - 复用创建使用现有 `createWishAction`，把历史标题、备注、碎片数作为隐藏字段提交。
- 统计信息：
  - MVP 前端从 `wishHistory` 计算。
  - 后续可新增 `/children/{childId}/wishes/stats` 降低客户端计算。

### 后续增强

- 心愿卡模板库表：保存主题、封面、默认碎片数、创建来源。
- 心愿卡图片生成：新增 AI worker 或 media workflow，生成 `wish_image` 并关联 `image_media_id`。
- 历史详情接口：`GET /wishes/{wishId}/history-detail`，聚合兑换、照片、纪念册、关联任务。

## 8. 实施步骤拆解

1. 文档阶段
   - 写入本方案文档，明确 MVP 和后续增强边界。

2. 后端聚合
   - 在 wishes DTO/service 中增加历史心愿项响应。
   - 在 parent dashboard 中返回 selected child 的 `wishHistory`。
   - 保持 `JdbcClient`、`FamilyPolicy` 权限校验和现有服务边界。

3. 家长端数据映射
   - 扩展 `dashboard-data.ts`，映射 wishHistory、redemption photos、统计所需字段。
   - fixture 数据提供本地兜底历史卡。

4. 家长端心愿页
   - 重构为当前心愿、统计、心愿卡库、历史心愿四区。
   - 实现碎片格组件。
   - 实现从历史卡复用创建。

5. 家长端计划页
   - 增加计划驾驶台、周节奏、模板卡视觉。
   - 保留现有 PlanEditor 行为。

6. 学生端 App
   - 重构 `wish_screen.dart` 为儿童友好心愿卡。
   - 增加碎片格、鼓励语、规则弹窗。

7. 验证
   - parent-web TypeScript 检查按要求在容器内运行。
   - Flutter 若宿主无 SDK，则说明未能本地验证，并保证代码遵循现有风格。
