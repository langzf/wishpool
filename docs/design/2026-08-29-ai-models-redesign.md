# AI 模型管理页重新设计

## 问题诊断

截图确认对应 `apps/admin-web/app/ai-models/page.tsx` 的 `/ai-models` 页面，不是参考样板，而是当前真实渲染结果。

### 视觉病灶

- **主内容像一张被撑开的空白画布**：供应商面板横向接近全屏，但每条模型信息只占左侧一小块，右侧只有孤立的 `modelName`。视觉重心被大片空白吞掉，用户需要扫很远才把“模型名称、状态、真实模型标识”拼起来。
- **列表行没有明确容器感**：当前 `image-model-row` 默认透明，只在 hover 时出现边框和底色。静态状态下，模型之间靠巨大竖向空白分隔，看起来像散落文本，而不是可管理对象。
- **层级过重又不准**：页面 H1、面板标题、模型标题、导航文字、状态文字都偏粗偏大，缺少“标题、元信息、辅助说明”的收束。移动端还把模型标题放大到 26px、元信息放大到 21px，进一步破坏信息密度。
- **状态标签重复且语义分散**：标题旁有“启用”，下面又有“接口状态 可用”。两个绿标签重复表达同一事实，占据大量纵向空间，却没有提供更多判断依据。
- **操作按钮像未完成的占位块**：四个图标按钮等权排列，语义色只有删除是红色；编辑、设默认、启停缺少清晰 hover/disabled/pending 差异，用户很难快速判断哪些动作可执行。
- **配色缺少页面专属气质**：深色侧栏和浅色内容区本身可用，但主面板只有白底、浅蓝边框和常规蓝按钮，缺少配置中心应有的精密、稳定和层次。
- **文案源文件出现中文乱码**：页面入口、组件、导航和弹窗源码中存在大量 mojibake 文本，说明当前实现的文本维护不可控，会直接损害管理端可信度。

### 交互病灶

- **高频动作反馈不足**：设默认、启停、删除虽然使用 server action，但用户只能看到小 spinner 或页面跳转后的提示，当前行没有明显“处理中”反馈。
- **删除依赖浏览器确认框**：浏览器 confirm 生硬、不可样式化，和页面视觉系统断裂；用户误点后体验突然跳出当前上下文。
- **弹窗关闭缺少退出过渡**：打开时有入场动画，关闭时立即卸载，交互显得硬。
- **表单校验反馈不完整**：`extra_params` 有 JSON 校验，但其他必填项主要依赖浏览器默认行为；错误、提示和提交按钮之间缺少统一的即时状态语言。
- **空态和加载态不够成体系**：空态只是普通虚线卡片，没有告诉管理员下一步；按钮和业务默认模型卡片虽然有 pending，但视觉反馈不够统一。
- **窄屏兜底失真**：移动端字号变大、按钮变大，模型名和状态会挤压主要内容，和管理端需要的可扫描性相反。

### 根因分析

当前实现把“好看的大卡片”和“管理后台列表”机械拼接在一起：容器变大了，但信息模型没有重排；按钮图标化了，但交互状态没有设计；状态标签上色了，但没有做语义压缩；弹窗承载了复杂配置，却没有完整的表单体验。结果是页面同时缺少传统后台的效率，也缺少现代 SaaS 的精致层次。

## 重新设计方案

### 设计方向

采用 **明亮现代 SaaS + 轻量控制台质感**。

理由：这是家庭心愿平台的管理端，需要可靠、清晰、可扫描，而不是纯黑科技风；同时它管理 AI 图片生成配置，适合加入细腻的蓝绿状态、紧凑数据芯片、轻量光感和更明确的操作反馈，摆脱传统白卡片老后台。

气质关键词：清爽、精密、克制、可扫描、可信任。

### 视觉规格

- **配色**
  - 页面背景：`#f4f7fb`，局部使用浅蓝径向光感。
  - 主文字：`#101828`，次级文字：`#536275`，弱文字：`#7b8798`。
  - 主蓝：`#2f6be6`，hover：`#2459ca`，浅蓝底：`#eaf2ff`。
  - 成功绿：文字 `#137a4b`，底 `#dcfce7`。
  - 默认金：文字 `#9a5b00`，底 `#fff0c2`。
  - 停用灰：文字 `#64748b`，底 `#eef2f7`。
  - 危险红：`#dc2626`，危险浅底 `#fff1f2`。
- **字体层级**
  - 页面 H1：42-56px，根据 viewport clamp，但不用于卡片内部。
  - 面板标题：26-30px。
  - 模型名称：20-22px。
  - 元信息：13-15px，使用中等字重。
  - 标签：12-14px，固定高度，避免跳动。
- **间距与容器**
  - 主面板改为“头部摘要 + 模型网格/列表”的结构。
  - 模型项使用有底色、有边框、有轻阴影的独立卡片行，默认就能看出对象边界。
  - 模型卡片内部分三区：身份区、状态与配置摘要区、操作区。长模型标识放在 `code chip` 中，允许换行。
  - 业务默认模型区作为次级面板，三张紧凑卡片展示，不抢主面板视觉优先级。
- **圆角与阴影**
  - 页面主面板 18px，模型卡片 16px，按钮 10-12px，标签 999px。
  - 阴影使用低透明度蓝灰，不做厚重投影。
- **图标风格**
  - 继续使用 `lucide-react`。
  - 主入口使用 `Plus`；模型卡片使用 `Sparkles`/`Cpu` 的组合语义；操作继续用 `Pencil`、`Star`、`Power`、`Trash2`。
  - 图标按钮保留 tooltip/title 和 aria-label。
- **状态与标签**
  - `默认`、`启用/停用`、`接口可用/已停用` 使用不同色系。
  - 右侧模型标识不再孤岛展示，而是和 `模型标识` 标签绑定。

### 交互规格

- **Hover/active**
  - 模型卡片 hover：轻微上移、边框变蓝、阴影增强、左侧图标产生轻微位移。
  - 图标按钮 hover：按动作语义变色；active 下压 1px。
- **提交与加载**
  - 所有 server action 按钮 pending 时显示 `Loader2` 并禁用。
  - 页面 query string 的成功/失败反馈显示为顶部 toast 样式提示，带入场动画。
- **删除确认**
  - 删除按钮第一次点击切换成行内确认区，显示“确认删除”和“取消”，避免浏览器 confirm 的割裂感。
  - 默认模型仍禁止删除。
- **弹窗**
  - 打开：遮罩淡入，面板轻微上浮。
  - 关闭：遮罩和面板播放 180ms 退出动画后卸载。
  - 移动端：弹窗变底部 sheet，宽度占满，最大高度 92dvh。
- **表单校验**
  - 必填项保留浏览器原生校验。
  - `extra_params` 客户端实时 JSON 校验；错误时 textarea 红色边框、显示中文错误、禁用提交。
  - 字段提示全部中文，编辑时明确说明编码不可修改、API Key 留空不变。
- **空状态**
  - 展示图标、标题、说明和新建按钮，强调“先接入一个可用模型”。
- **窄屏兜底**
  - 模型卡片改为单列，操作按钮换行但保持 44px 点击目标。
  - 不在移动端放大模型文字，保持扫描效率。

## 实现范围

- 修改 `apps/admin-web/app/ai-models/page.tsx`：修正中文文案，增加页面级说明和反馈 class。
- 修改 `apps/admin-web/components/AiModelManager.tsx`：重排模型卡片结构、行内删除确认、表单即时校验、中文文案。
- 修改 `apps/admin-web/components/Modal.tsx`：增加退出动画状态，修正中文描述。
- 修改 `apps/admin-web/components/AdminShell.tsx`、`apps/admin-web/components/AdminSideNav.tsx`、`apps/admin-web/components/FormSubmitButton.tsx`：修正页面可见乱码。
- 修改 `apps/admin-web/app/styles.css`：重做 AI 模型页、弹窗、按钮、业务默认模型和响应式样式。
- 不修改 `apps/admin-web/app/actions.ts`：server action 与后端接口行为保持不变。
- 不修改其他应用模块：本次问题限定在管理端 AI 模型管理页。

## 关键设计取舍记录

- 不改成传统表格。模型供应商数量通常少，卡片行能更好承载状态、配置摘要和快捷动作。
- 不使用纯深色科技风。深色侧栏已经提供控制台基调，内容区保持明亮能提升表单可读性。
- 不新增动画库。动效全部用 CSS transition/keyframes 和已有 `useFormStatus` 完成。
- 删除使用行内二次确认，而不是新弹窗。这样减少状态复杂度，也避免和编辑弹窗竞争。
- `extra_params` 做前端即时校验，但最终仍由 server action 解析并提交，前端只负责提前拦截低级错误。
