# AI 模型管理页样式与交互重做

## 参考图解读

参考图对应当前 admin-web 的 `/ai-models` 页面，而不是 parent-web 或其他业务页。依据是画面中明确出现“配置中心 / 图片生成”“AI 模型管理”“图像生成供应商”“2/2 启用”“新建模型”，并且列表项字段与现有 `ImageModelProvider` 数据结构一致。

视觉方向是轻量但有亲和力的治理后台：左侧深海军蓝固定导航，右侧是接近白色的浅灰画布；标题使用圆润厚重字体，字号很大，和传统后台的紧凑小字区分开。主体是一个宽大的白色面板，边框极浅、阴影柔和，圆角约 14-16px。状态标签使用柔和色块：蓝色计数、绿色启用/可用、浅黄色默认，文字粗且饱满。列表不是表格，而是纵向信息块：左侧星光图标作为模型类型标记，中间是名称、供应商类型、编码、接口状态和操作按钮，右侧以大号文本展示真实模型名。

交互方向是“配置集中在弹窗，列表负责快速操作”。参考图暗示所有高频动作以小方形图标按钮呈现，按钮需要明确 hover、active、disabled 状态；新建是右上角主按钮，状态计数像胶囊标签一样稳定展示。弹窗应承担复杂字段编辑，出现时需要轻量遮罩和入场动效；表单需要即时校验，特别是 JSON 扩展参数不能等提交失败才反馈。操作提交应有加载态，避免用户重复点击。

## 差距分析

- 当前页面虽然已有大致结构，但视觉层级仍偏“拼出来”：列表项缺少细腻的 hover 背景、焦点光晕和行内操作反馈，面板内部留白与参考图的宽松节奏不完全一致。
- 图标按钮只是可点击方块，缺少“编辑 / 设默认 / 启停 / 删除”之间的语义色彩、提交中状态和可感知反馈。
- 弹窗只在打开时挂载，关闭没有退出过渡；表单字段缺少说明、即时校验和错误定位，`extra_params` JSON 出错时只能依赖后端异常。
- 删除是直接提交，交互风险高；设默认、启停等表单提交没有 pending 文案。
- 空状态过于普通，没有把参考图的星光视觉语言延伸进去。
- 成功/失败反馈是普通提示条，缺少固定位置、轻微动效和“操作完成”的即时感。
- 窄屏下行项目字号被放得过大，容易让模型名、状态和操作按钮挤压，和参考图的稳重气质不一致。

## 落地设计

- 页面布局：保留 `AdminShell`，AI 模型页顶部继续使用面包屑 + 大标题。主体仍为 12 栏网格，但供应商面板作为第一视觉重点，业务默认模型作为下方辅助区。
- 供应商面板：白色大面板、浅蓝边框、柔和阴影、16px 圆角；头部左右分布，左侧标题和说明，右侧启用计数 + 主按钮。
- 供应商列表：保持参考图的“无表格、无分割线重压”结构。每个模型行使用两列布局，左侧信息密集但留白充足，右侧显示 `modelName`。hover 时使用极浅蓝底、边框显形、轻微上移，操作按钮随行 hover 更清晰。
- 状态标签：`默认` 使用浅黄色底、棕金色文字；`启用/可用` 使用浅绿色底、深绿色文字；`停用` 使用灰蓝底。标签尺寸稳定，避免内容变化造成跳动。
- 操作按钮：使用 lucide 图标。编辑保持深色；设默认使用星形，启用后可点击，当前默认禁用；启停使用电源图标；删除使用红色。hover 有边框加深、背景变色和轻微上移；active 下压；提交中显示小 spinner 并禁用。
- 弹窗：遮罩使用深色半透明 + 桌面模糊；面板从下方轻微浮入，头部带配置语境，关闭按钮右上角。移动端贴近底部作为 sheet，宽度占满。
- 表单交互：字段按两列布局，`extra_params` 跨列。必填字段使用浏览器校验，同时 CSS 提供 `:invalid` 的边框反馈；`extra_params` 增加客户端 JSON 校验，实时显示“JSON 格式正确/错误”，错误时禁用提交按钮。提交按钮显示保存中。
- 空状态：使用星光/密钥图标、大标题、说明和主按钮，背景保持浅蓝白，不做夸张插画。
- 业务默认模型：作为次级面板，保留三张业务卡片，但统一 hover、select focus、提交 loading，使其与主面板同一套控件语言。
- 成功/失败反馈：提示条增加图标感、左侧色条和轻微入场动效，放在标题和内容之间。
- 窄屏兜底：侧栏自然转为顶部区域；面板头部堆叠；模型行切成单列；右侧模型名变成左对齐标签区；按钮保持固定 44-48px 点击区域，避免重排。

## 实现范围

- 修改 `apps/admin-web/components/AiModelManager.tsx`：增加提交 loading、删除确认、JSON 即时校验、表单辅助反馈和更语义化的状态 class。
- 修改 `apps/admin-web/components/Modal.tsx`：补充弹窗描述 id、关闭按钮 class，维持既有 API。
- 修改 `apps/admin-web/app/ai-models/page.tsx`：为提示、业务默认模型卡片补充状态 class 和禁用空状态。
- 修改 `apps/admin-web/app/styles.css`：集中重做 AI 模型页、弹窗、按钮、提示、业务卡片的样式和动效。
- 不修改 `apps/admin-web/app/actions.ts`：后端接口与 server action 行为保持不变。
- 不修改其他应用模块：本次问题限定在管理端 AI 模型管理页。

## 决策记录

- 保留参考图的大面板列表形态，不改成表格。模型配置是少量运维对象，卡片式列表比表格更符合参考图，也更适合展示状态和快捷动作。
- 不引入动画库。所有动效用 CSS transition/keyframes 和 `useFormStatus` 完成，避免增加依赖和运行风险。
- `extra_params` 在客户端做 JSON 校验，但最终仍由 server action 解析。前端校验用于减少低级错误，后端校验仍是权威。
- 删除增加浏览器确认。虽然不是定制弹窗，但能在不新增复杂状态和接口的前提下降低误删风险。
- 业务默认模型不抢主视觉。参考图核心是供应商面板，因此业务默认模型只跟随同一套控件语言，不做同等强度的视觉强调。
